## Как данные попадают в БД (важно для новой недели)

1. БД (`data/hmnd.db`) **эфемерна** и в git не хранится — она пересобирается из файлов
   в `sources/` командой `python -m scripts.sync` (или `scripts.reset`).
2. На каждого провайдера `sync` берёт **только самый свежий файл** — по дате в имени
   (`*_YYYYMMDD.json`). Остальные файлы того же провайдера игнорируются.
3. Период загрузки/перезаписи берётся **не из имени файла, а из `_meta.rangeStart/rangeEnd`
   внутри JSON**. Загрузчик идемпотентен: сначала `DELETE` событий провайдера за этот
   период, потом `INSERT`. Повторная загрузка того же файла не плодит дубликаты.

## Как ДОБАВИТЬ новую неделю, чтобы «в БД всё было правильно»

Дату в имени нового файла бери **позже** `20260515` (например, дата выгрузки —
`Anthropics_20260522.json`), иначе `sync` продолжит брать старый файл.

Дальше — два варианта, и это решает всё:

### Вариант A (рекомендуется, как сейчас и устроено): кумулятивная выгрузка
Новый JSON покрывает **тот же старт** `2026-02-12` и **новый конец** (например `2026-05-20`),
т.е. `_meta.rangeStart = 2026-02-12`. Тогда новый файл перетирает весь период и в БД
оказывается полная история + новая неделя. Старые `*_20260515.json` остаются как бэкап.
Текущие файлы именно такие (старт `2026-02-12`), так что безопаснее всего держать тот же формат.

### Вариант B: выгрузка только за новую неделю (инкремент)
Новый JSON покрывает **только новую неделю** (`_meta.rangeStart = 2026-05-14`).
⚠️ При полной пересборке БД `sync` загрузит **только** этот недельный файл, а история
`2026-02-12 → 2026-05-13` потеряется (старый файл уже не «самый свежий»).
Чтобы так делать безопасно, нужно либо (а) доработать загрузчик, чтобы он грузил **все**
файлы провайдера (от старых к новым, с идемпотентным `DELETE`-по-периоду — тогда
непересекающиеся недели складываются), либо (б) всё-таки делать выгрузку кумулятивной (Вариант A).

> Если планируешь Вариант B — скажи, я внесу правку в `data/sources/*` и `backend/services/sync.py`,
> чтобы грузились все файлы, и добавлю тест.

## Восстановление

Вернуть исходные файлы из бэкапа:
```bash
cp backups/2026-05-28/sources/*.json sources/
cp "backups/2026-05-28/sources/git_repos.txt" sources/
python -m scripts.reset --days 200      # пересобрать БД из источников
```

Поднять материализованный снимок БД напрямую (без пересборки):
```bash
gunzip -c backups/2026-05-28/hmnd_snapshot.sql.gz | sqlite3 data/hmnd.db
```

## Проверка целостности бэкапа
```bash
cd backups/2026-05-28
python3 - <<'PY'
import hashlib, json, pathlib
m = json.load(open("MANIFEST.json"))
bad = 0
for rel, meta in m["files"].items():
    h = hashlib.sha256(pathlib.Path(rel).read_bytes()).hexdigest()
    if h != meta["sha256"]:
        print("MISMATCH:", rel); bad += 1
print("OK" if not bad else f"{bad} mismatch(es)")
PY
```
