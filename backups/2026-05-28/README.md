## Как данные попадают в БД (важно для новой недели)

1. БД (`data/hmnd.db`) **эфемерна** и в git не хранится — она пересобирается из файлов
   в `sources/` командой `python -m scripts.sync` (или `scripts.reset`).
2. На каждого провайдера `sync` грузит **все** файлы — от старых к новым (по дате в имени
   `*_YYYYMMDD.json`).
3. Период загрузки/перезаписи берётся **не из имени файла, а из `_meta.rangeStart/rangeEnd`
   внутри JSON**. Загрузчик идемпотентен: сначала `DELETE` событий провайдера за этот
   период, потом `INSERT`. Повторная загрузка того же файла не плодит дубликаты;
   непересекающиеся недели складываются, а на пересечении побеждает более свежий файл.

> Это поведение включено правкой в `backend/services/sync.py` (грузятся все файлы, а не
> только самый свежий) и закреплено тестом
> `tests/test_sync.py::test_incremental_weekly_anthropic_json_accumulates`.

## Как ДОБАВИТЬ новую неделю, чтобы «в БД всё было правильно»

Дату в имени нового файла бери **позже** `20260515` (например, дата выгрузки —
`Anthropics_20260522.json`). Старые `*_20260515.json` **оставь на месте** — они теперь
тоже грузятся. Подходит любой из двух форматов выгрузки:

### Вариант A: кумулятивная выгрузка (как сейчас)
Новый JSON покрывает тот же старт `2026-02-12` и новый конец (например `2026-05-20`),
т.е. `_meta.rangeStart = 2026-02-12`. Новый файл перетирает весь период — в БД полная
история + новая неделя.

### Вариант B: выгрузка только за новую неделю (инкремент) ✅ теперь поддерживается
Новый JSON покрывает **только новую неделю** — выставь `_meta.rangeStart` на **день после**
конца предыдущего файла (т.е. `2026-05-14`, раз прошлый закончился `2026-05-13`), а
`_meta.rangeEnd` — конец недели. История `2026-02-12 → 2026-05-13` остаётся из старого
файла, новая неделя добавляется из нового. Не делай старт раньше `2026-05-14`, иначе
пересекающиеся дни перезапишутся данными только из нового (неполного) файла.

Сделай по три файла на неделю (Anthropic / Cursor / OpenAI) с одинаковым периодом внутри.

После добавления — пересобери и сверь с эталоном:
```bash
python -m scripts.reset --days 200    # полная пересборка из всех файлов sources/
```
Числа за `2026-02-12 → 2026-05-13` должны совпасть с `SNAPSHOT_METRICS.json`, плюс
добавятся события новой недели.

## Восстановление

Вернуть исходные файлы из бэкапа:
```bash
cp backups/2026-05-28/sources/*.json sources/
cp "backups/2026-05-28/sources/git_repos.txt" sources/
python -m scripts.reset --days 200      # пересобрать БД из источников
```

Поднять материализованный снимок БД напрямую (без пересборки):
```bash
gunzip -c backups/2026-05-28/hmnd_snapshot.sql.gz | sqlite3 data/hmnd.db
```

## Проверка целостности бэкапа
```bash
cd backups/2026-05-28
python3 - <<'PY'
import hashlib, json, pathlib
m = json.load(open("MANIFEST.json"))
bad = 0
for rel, meta in m["files"].items():
    h = hashlib.sha256(pathlib.Path(rel).read_bytes()).hexdigest()
    if h != meta["sha256"]:
        print("MISMATCH:", rel); bad += 1
print("OK" if not bad else f"{bad} mismatch(es)")
PY
```
